# 安装：pip install -r requirements.txt
#
# ── 版本约束约定 ──────────────────────────────────────────────────────────────
# 每条都写成  包名 >= 下界,< 上界 ：
#   · 下界 = 本仓库实测通过的版本（与 requirements.lock 一致）
#   · 上界 = 下一个「预期可能破坏兼容」的版本
#
# 收口粒度按破坏性变更风险分档：
#   · AI 编排栈（langchain / langgraph 系）—— 收口到次版本
#     这类包在小版本间就会改 API（如 langchain 1.x 的 create_agent 迁移），
#     放宽会让「换机重装」装到未验证的 API 表面上。
#   · 求解器（highspy）—— 收口到次版本，因为求解器版本会影响求解耗时与数值结果。
#   · 科学计算 / 机器学习 / Web 栈 —— 收口到主版本，允许次版本与补丁升级。
#
# ── 为什么要收口 ──────────────────────────────────────────────────────────────
# 早期使用 `~=` 宽松约束时，全新安装实测会解析到 langchain 1.4.0、
# langchain-core 1.6.3、uvicorn 0.53.0 等**未经本项目验证**的版本
# （因为 `~=1.3` 等价于 >=1.3,<2.0，允许跨次版本升级），
# 与 requirements.lock 记录的实测环境不一致，存在"别人装完跑不起来"的风险。
#
# ── 逐版本精确复现 ────────────────────────────────────────────────────────────
# 需要与实测环境完全一致（生产 / CI）时用：
#     pip install -r requirements.lock
#
# 维护约定：改动本文件的下界时，必须同步 requirements.lock 并重跑 pytest。
# ==============================================================================
