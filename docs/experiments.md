## 1. 调度优化：基准 vs MILP vs 无热约束

以调度日 2024-07-30 为例，三种策略对比：

| 指标 | 基准策略（谷充尖放） | MILP 优化（稳态） | 无热约束上界 |
|------|-------------------|------------------|-------------|
| 日套利收益 | 841.75 元 | 1816.27 元 | 2006.54 元 |
| 日衰减成本 | 130.04 元 | 388.37 元 | 530.10 元 |
| 日净收益（套利 − 衰减） | 711.71 元 | **1427.90 元** | 1476.44 元 |
| 日充电量 / 放电量 | 842.1 / 760.0 kWh | 2505.7 / 2261.4 kWh | 2947.4 / 2660.0 kWh |
| 最高电池温度 | 42.34 ℃ | 46.92 ℃（降额区） | 57.23 ℃（已越过 55 ℃ 停机阈值） |
| 等效循环 | 0.4877 次 | 1.4564 次 | 1.9879 次 |
| 求解时间 | < 0.1 s | 40.2 s（HiGHS，`mip_gap` 代码默认 **1%**） | 3.9 s |

> 三列全部为 2026-09-20 在 331 号文电价日历下重测。基准列的充/放电量（842.1 / 760.0 kWh）
> 与 2026-09-07 的旧记录一致到小数点后一位——两档窗口的长度确实变了，但这一列原来就未单独
> 复核，本轮才补上；是否纯属巧合未做溯源。
> 无热那一列的 DR 补贴是 **0 元**（两个默认事件都被拒：预测温度 72.3 ℃ 越线、SOC 不足），
> 所以它的"净收益"里不含任何 DR 成分，与含热列比较时这一点必须说明。

口径说明：本表「日净收益」列统一为**套利 − 衰减**（不含 DR 补贴），与基准策略同口径。

### 复现脚本（2026-09-20 在 331 号文口径下重测通过）

量化成果表那一列是**整轮运行**（含页面默认的两个 DR 事件）产出的，不是单次 MILP——
直接调 `optimize()` 得到的是基础调度，套利/衰减/净收益都对不上表里的 1816.27 / 388.37 /
1427.90。复现必须走协调器：

```python
from src.utils.config import CONFIG
from src.agents.coordinator_agent import CoordinatorAgent, DRSignal
from src.data.data_loader import load_load_data

D = "2024-07-30"
DR = [DRSignal(start_time=f"{D} 15:00", end_time=f"{D} 17:00", target_reduction_kw=400.0,
               subsidy_per_kwh=0.8, dr_type="peak_shaving"),
      DRSignal(start_time=f"{D} 11:00", end_time=f"{D} 12:00", target_reduction_kw=500.0,
               subsidy_per_kwh=1.0, dr_type="peak_shaving")]
rep = CoordinatorAgent(CONFIG).run_daily_scheduling(
    date=D, historical_data=load_load_data(), dr_signals=DR,
    use_ml_forecast=True, include_thermal=True, include_degradation=True)

# 判据写成断言，免得把"口径差"当成"复现成功"：
assert abs(rep.arbitrage_revenue_yuan - 1816.27) < 0.5, rep.arbitrage_revenue_yuan
assert abs(rep.degradation_cost_yuan - 388.37) < 0.5, rep.degradation_cost_yuan
assert abs(rep.max_battery_temp_c - 46.92) < 0.2, rep.max_battery_temp_c
assert abs(rep.equivalent_cycles - 1.4564) < 0.01, rep.equivalent_cycles
print(rep.net_revenue_yuan)   # 1587.74 = 表内 1427.90 + DR 补贴 159.84
```

本轮实测（2026-09-20，开发机 Python 3.13.9，整轮 40.2 s）：

- **上面四条断言全部通过**，即量化成果表的 `MILP 优化（稳态）` 一列可复现。
  表内「日净收益」不含 DR 补贴，所以 1587.74 与 1427.90 是同一个解的两种口径。
- **`mip_gap` 从 1% 收到 0% 没有换来收益，是反例**（同一输入：96 点、含热、区间加权）：
  求解 39.1 s → **303.3 s**（7.8 倍），目标函数值只动 **+0.67 元**（1379.53 vs 1378.86），
  报表净收益反而 **少 31.79 元**（1341.79 vs 1373.58，−2.31%）。根因是两套衰减计费不同源：
  gap 0% 那条曲线目标内计 382.54 元、后验重算 420.29 元，**差 37.75 元（占后验 9.0%）**；
  gap 1% 那条只差 5.28 元。旧版本这里写过"1% 容差的代价是 2.9% 收益"，
  那是**旧电价 + 错误输入**下的另一个解，两个结论都不该外推。
- **SOC 区间加权 vs 常数近似**（`soc_weighted_degradation` 开关，两者净收益均由同一套
  后验区间加权成本结算，可比）：区间加权 **1373.58** vs 常数近似 **1346.23**，
  差 **+27.35 元（+2.03%）**。常数系数给它自己那条曲线计衰减 557.81 元，后验真实值
  384.30 元（**高估 45.1%**），于是它让出 30.55 元套利而真实衰减几乎没省（反而多 3.19 元）。
  等效循环 1.4411 vs 1.4531，最高温 44.86 vs 44.73 ℃。方向由
  `tests/test_storage_agent.py::test_soc_weighted_degradation_improves_decisions`（`slow`）守着。
  > ⚠️ **这两组对比此前都在"气温被静默丢弃"的输入上测的**：调用形如
  > `optimize(PRICE, AMB)`，而签名第二位是从未被读取的 `load_profile`，气温于是退化成
  > 常量 30 ℃。旧结论"精确模型相对常数近似当天只多 1.67 元（0.14%）"因此从来没有被
  > 正确输入支撑过（它当时被写成"这是一个诚实的空结论"）。参数已删除、第二位现在是真正的
  > `ambient_temp_profile`，本节数字按修正后的调用重测。
- **寻优路径的输入也已同源**：`ParameterSearchAgent._day_series` 过去自己调
  `generate_ambient_temp` 抽气温（未播种），改为读当日落盘序列后，96 点 `evaluate()`
  与本节直接调 `optimize()` 得到同一个数 **1373.58 元**——两条路径首次逐分对齐。
  同输入重复求解实测**逐分不差**，所以"求解器抖动 1%"这条门槛论证已改写为
  "门槛只需盖住 1% 容差"。

### 关键发现

1. **优化 vs 基准 +100.6%**（711.71 → 1427.90 元/天）：差异主要来自 MILP 发现
   "峰价充电 + 尖峰放电"的二次套利机会（基准 0.4877 次等效循环 → 优化 1.4564 次）。
2. **热约束的代价 −3.3%**（48.54 元/天）：换来温度从 57.23 ℃（已越过 55 ℃ 停机阈值）
   降到 46.92 ℃（进入 45–55 ℃ 线性降额区，距 55 ℃ 仍有 8.1 ℃ 余量）。
   旧电价口径下同一笔交易是 8.5% —— **换一套时段划分就会换这个数**，所以它必须和电价
   口径绑在一起引用，单独写"热约束值 8.5%"是没有出处的。
3. **稳态口径 vs 单日口径**：本表「日净收益」不含 DR；含 DR 的整轮报表净收益 1587.74 元/天。
   两者都在稳态约束（`SOC[96] == SOC[0]`）下解出，不含"把初始 SOC 放空"的账面收益。
   真正不可持续的是**假设天天有 DR**：按 50 天/年进年化只加 0.8 万元，按 365 天计会虚高到
   58.0 万元。稳态同口径 **1427.90 元/天 × 365 ≈ 52.1 万元/年** 才是能拿到的数。

### 年化口径三选一（务必说明用哪个）

| 口径 | 计算式 | 结果 | 含义 |
|------|--------|------|------|
| **同口径（推荐对外使用）** | (套利 − 衰减) × 365 | **52.1 万元/年** | 与基准策略同口径，不含 DR 补贴 |
| 含 DR（`/api` 的 `annual.net`） | (套利 − 衰减) × 365 + DR补贴 × 50 | **52.9 万元/年** | DR 按"每周约 1 次有效事件 ≈ 50 天/年"计入 |
| DR 每天都有（**不成立**） | 单日净收益(含 DR) × 365 | 58.0 万元/年 | 假设每天都有 DR 事件，与广东实际补贴频次不符 |

> DR 事件全年的实际出现频次取决于当地电网邀约，系统内按 50 天/年建模，
> 这是**显式假设而非实测值**。

## 2. 负荷预测精度（30 天实测，2024-07-30 调度日）

| 方法 | MAPE | 复核状态 |
|------|------|----------|
| 项目 XGBoost + 物理修正 | 3.12% | ✅ 本次已复核 |
| **朴素基线**（过去 14 天、分工作日/周末、同时刻均值） | **3.01%** | ✅ 本次已复核 |
| XGBoost（去掉温度特征，纯 ML） | 2.98% | ⚠️ **未复核**（2026-09-07 记录） |
| XGBoost（去掉温度特征 + 物理修正）ablation | 2.99% | ⚠️ **未复核**（2026-09-07 记录） |

**结论**：XGBoost 仍略输朴素基线 0.11 个百分点（原记录为 0.45 个百分点，本次复核后缩小）。

**原因**：合成数据是确定性日模式 + 3% 噪声，规律性极强，朴素基线天然占优。

**改进方向**：

1. 改用直接多步预测（不递归喂回预测值）；
2. 至少跑一份公开数据集（如 NREL ComStock）做外部验证；
3. 物理修正作为 ablation 开关，**不**默认开启。

### 防幻觉守卫 `check_grounding()` 实测（2026-09-18，调度日 2024-07-30）

| 探针 | 埋入的编造数字 | 结果 |
|------|--------------|------|
| `gp-fabricated-money` | `4521.00 元`、`1.62 元/kWh` | 全部拦下 |
| ~~`gp-fabricated-money` 曾埋 `0.87 元/kWh`~~ | 同一个位置 | **改版后失效**：331 号文口径下摘要里出现 `0.88`，守卫按容差判它有依据，于是放行，捕获率 0.750 → 0.500 |
| `gp-fabricated-temp` | `71.5 ℃`（已越过 55 ℃ 停机线） | 拦下 |
| `gp-rounding-ok` | 无（真数字取整到个位） | 零误报 |
| `gp-count-words` | 无（无单位计数词） | 零误报 |
| `gp-clean-report` | 无（整段照抄摘要） | 零误报 |
| `gp-unit-boundary` | `0.9 倍` | **漏网 —— 已知盲区** |

- 捕获率 **0.750**（4 个埋入数字拦住 3 个），误报率 **0.000**。
- 盲区根因：`_UNIT_NUM_RE` 的单位白名单为 `元/kWh|元|kWh|kW|℃|%|次`，不含"倍"，
  因此"0.9 倍"这类比率表述**根本不进入校验**。已在
  `tests/test_evals.py::test_known_blind_spot_unit_outside_whitelist` 里把"漏网"钉成断言：
  将来补全白名单后这条会红，提醒回来把断言翻成"拦住"。写进指标而不是从用例里删掉，
  才是可引用的结论。
- **第二个盲区是数值容差带，本轮被电价改版撞出来**：`check_grounding(rtol=0.01, atol=0.05)`，
  其中 `atol=0.05` 不是随手定的——事实摘要自己就把价格印成两位小数（`1.105 → 1.1`、
  `0.247 → 0.25`），容差小于 0.05 会把真数字判成编造。代价是在元/kWh 这个量级上，
  与真实值相差不超过 **0.05 元/kWh（约 6%）** 的编造数字一律放行。
  探针原先埋的 `0.87 元/kWh` 就落在摘要 `0.88` 的带内，于是"编造"被守卫认为有依据，
  `grounding_catch_rate` 从 0.750 掉到 0.500。**指标掉的是探针效度，不是守卫能力**。
  现已把埋值改成 `1.62 元/kWh`（在任何真实值的容差带之外），并由
  `tests/test_evals_run.py::test_planted_numbers_are_not_accidentally_grounded`
  把"埋的数必须真的不在摘要里"钉成断言：以后改口径再撞上，这条会红并点名相撞的真实值。
- 降级链（无 Key / 客户端抛异常 → 规则模板）仍由 `tests/test_llm_explainer.py` 覆盖。
  上面这张表是 mock 路径；**真实模型回归已于 2026-09-19 补跑，结果见下面的 §3.1**。

### 3.1 真实模型回归（2026-09-19，`deepseek-flash`）

`python -m evals.run_eval --mode llm --model deepseek-flash` —— 35 例 / 0 跳过 / 0 异常 / 347 秒，
报告入库 [`evals/reports/llm-latest.md`](../evals/reports/llm-latest.md)。

| 指标 | 规则模式 | 真实模型 `deepseek-flash` | 说明 |
|---|---|---|---|
| 任务成功率 | 0.969（31/32） | 0.914（32/35） | **换算到同分母的 32 例是 0.938，比规则模式低 3.1 个百分点** |
| 数字保真 | 1.000 | 1.000（9 例带锚点） | 一致 |
| 副作用守卫 | 1.000 | 1.000（5 例） | 一致 |
| 编造捕获 / 误报 | 0.750 / 0.000 | 0.750 / 0.000 | 一致——守卫是同一套 `check_grounding`，与被路由的是谁无关 |
| 延迟 p50 / p95 | 0.1 / 1.3 ms | 5 073 / 28 831 ms | token 132 533 prompt + 32 257 completion |

三条失败的逐条归因写在 [`evals/README.md`](../evals/README.md) 的已知失败用例表里：两条是判分口径
（`must_contain` 用了规则模板的 `✅`/`❌` 表面符号，模型回答的事实部分完整且正确），一条是
`run_with_params` 的工具面根本表达不了那个假设问句。**没有为了让分数好看放宽任何断言。**

真实模型这一轮**新暴露**的事实（已写进主 README 的已知局限）：对话链路的回答不经过
`check_grounding()`，而它恰恰会产出摘要里没有的派生数字（396.47 − 21.6 → "净收益 374.9 元"）
和无工具依据的估算区间（"400–700 元"）。直接把回查接到对话路径会把合法算术全判成误报，
需要先加"可验算的派生表达式"这一档。

## 5. 数据口径注意事项

- `data/` 里的**负荷与气温是合成演示数据**，非真实计量数据，不可用于生产结算或容量规划。
  电价是例外：时段划分与峰:平:谷 = 1.7:1:0.38、尖峰 ×1.25 按**粤发改价格〔2021〕331 号**实现，
  但 0.65 元/kWh 只是示例平段基准价，不等于任何一户的实际到户价。逐条对应关系与改口径的
  注意事项见 [`data/README.md`](../data/README.md)。
- **改了电价时段口径必须把 `backend/server.py::PRICE_RULE_VERSION` +1**，否则磁盘上的旧求解
  缓存会顶着旧日历的价格被命中，症状是"改了代码但数字没变"。
- 需求响应按"放电量 × 补贴"结算，**未建模 CBL 基线**（真实结算按相对基线负荷的削减量），
  当前口径存在重复计利。
- **未建模需量电费**（容量电价），会低估工商业储能收益。
- 负荷预测的 `physical_correction` 在默认 data-driven 模式下，当 XGBoost 已含温度特征时
  斜率 ≈ 0（修正自动近零）；要让物理修正真正起作用需开启 `exclude_temp_features=True`。
