# `data/` 数据来源与口径

> 这个目录里的东西**不是同一类数据**，混在一起看会得出错误结论。逐文件说明如下。
> 一句话版本：**电价有出处，负荷与气温是合成的**。

## 1. `price_yuan_per_kwh` —— 有正式文件出处

**来源**：广东省发展改革委《关于进一步完善我省峰谷分时电价政策有关问题的通知》
（**粤发改价格〔2021〕331 号**，2021-08-31 发布）。

原文与本仓库实现的对应关系：

| 文件原文 | 本仓库实现 |
|---|---|
| 高峰时段为 10-12 点、14-19 点 | `PRICE_PERIODS["高峰"].range = [(10,12),(14,19)]` |
| 低谷时段为 0-8 点 | `PRICE_PERIODS["低谷"].range = [(0,8)]` |
| 其余时段为平段 | `[(8,10),(12,14),(19,24)]` |
| 尖峰电价执行时间为 **7 月、8 月和 9 月**三个整月 | `PRICE_PERIODS["尖峰"].months = (7,8,9)` |
| 尖峰每天执行时段为 11-12 时、15-17 时共三个小时 | `[(11,12),(15,17)]` |
| 尖峰在高峰电价基础上**上浮 25%** | `spike_price = peak_price × 1.25` |
| 峰 : 平 : 谷 = **1.7 : 1 : 0.38** | `peak = flat × 1.7`，`valley = flat × 0.38` |

时段划分的**唯一实现**是 `src/data/data_generator.py::PRICE_PERIODS`；
四个价格值由 `src/utils/config.py::PriceConfig` 按上面的比例推导，不是手填：

```
平段基准 0.65  →  高峰 1.105  →  尖峰 1.38125
             ↘  低谷 0.247
```

**必须知道的限制**：

- **0.65 元/kWh 是示例平段基准价，不是任何一户的实际到户电价。** 实际到户价含
  上网电价/代理购电价、输配电价、基金及附加，各月、各电压等级、珠三角与粤东西北都不同，
  且 2023 年后工商业目录销售电价已逐步被代理购电价格表取代。
  本仓库只保证**比例关系与时段划分**符合 331 号文，不保证绝对价格等于某张电费单。
- 尖峰 1.38125 **刻意不取整**：取整后 `尖峰 / 高峰` 就不再严格等于 1.25，
  比例一致性测试也会失败。
- 331 号文的适用范围是**工商业用户**（大工业及一般工商业）；居民另行规定，本仓库不涉及。
- 政策会变。改动前先查现行文件，改 `PRICE_PERIODS` 与 `PriceConfig` 后
  **必须把 `backend/server.py::PRICE_RULE_VERSION` +1**，否则磁盘上的旧求解缓存
  会顶着旧日历的价格被命中，症状是"改了代码但数字没变"。

## 2. `load_kw` —— 合成

`src/data/data_generator.py::generate_load_profile`，按"典型工商业日负荷形状 ×
温度修正"生成，基准 1500 kW（`LoadConfig.base_load_kw`），`seed=42` 可复现。
**不是真实计量数据**，不可用于生产结算或容量规划。

## 3. `ambient_temp_c` —— 合成

`generate_ambient_temp`：月度基准 + 日变化正弦 + 噪声。
它只是热模型的**环境边界条件示例**，既不是气象站观测气温，更不是电池箱体进风温度或电芯温度。
用真实气象数据替换是后续工作。

## 4. `dr_signals.csv` —— 离线示例，不在 Web 链路上

Web 流程按所选调度日自动生成两个默认 DR 事件（15:00-17:00 / 11:00-12:00，
均落在 331 号文的尖峰窗口内），
并支持页面手工触发与 `POST /api/dr/trigger`。
本 CSV 只被测试与命令行寻优脚本（`--with-dr`）引用，**改它不会改变界面上的 DR 事件**。

## 5. 基本电价（容（需）量电价）—— 有出处，但不在本目录的数据里

本目录只有**度电能量成本**相关的列。账单里与用电量无关的那一半（基本电费）
由 `src/utils/config.py::DemandTariffConfig` 一处定义、`src/utils/demand_charge.py` 计费，
放这儿是因为它和电价同属"计费口径"，改错了后果一样。

**规则来源**：《国家发展改革委办公厅关于完善两部制电价用户基本电价执行方式的通知》
（**发改办价格〔2016〕1583 号**，2016-06-30）。原文与实现的对应：

| 文件原文 | 本仓库实现 |
|---|---|
| 基本电价按变压器容量或按最大需量计费，**由用户选择** | `DemandTariffConfig.mode ∈ {"capacity", "contract", "actual", "none"}` |
| 选按最大需量的须签合同，**按合同最大需量计收** | `mode="contract"`（默认），`contract_demand_kw` |
| 实际最大需量**超过合同确定值 105% 时，超过部分加一倍收取** | `over_contract_band = 1.05`、`over_band_price_multiplier = 2.0` |
| **未超过 105% 的，按合同确定值收取** | 同上：月峰在阈值内 → 账单 = 核定值 × 需量单价，与削了多少峰无关 |
| 申请核定值**低于（变压器容量＋高压电动机容量）总和 40%** 时按 40% 核定 | `min_contract_capacity_ratio = 0.40`（`effective_contract_kw()`） |
| 合同核定值可提前 5 个工作日**按月变更** | 未建模时间维度；`--contract-sweep` 给出申报值的敏感性 |
| 两路及以上进线**分路计算、累加计收** | 未建模（本仓库是单并网点口径） |

**单价来源**：广东省电网企业代理购电工商业用户电价表（**惠州市**，执行时间 2026 年 2 月），
两部制 1–10（20）千伏栏——最大需量 **36.1 元/千瓦·月**、变压器容量 **22.6 元/千伏安·月**。
同一张表的其他电压档：35–110 千伏 31 / 19.4，220 千伏及以上 26.1 / 16.3；
**单一制用户这两栏是「/」**，即不收基本电费（所以 `mode="none"` 必须能表达）。
参考：<http://dgdp.dg.gov.cn/zwgk/zfxxgkml/zcwj/qtwj/content/post_4385456.html>（1583 号全文）、
<https://www.huidong.gov.cn/hdxwz/ztlm/ggqsyxxgk/gogndian/content/post_5714024.html>（该电价表页）。

**必须知道的限制**：

- 单价是**某一地市、某一个月**的代理购电价表，不是全广东省统一价，也不是长期价。
  换地市/换月份要重取这两个数，代码里没有第二份（`tests/test_demand_charge.py` 有守卫）。
- 需量按**整月最大**计收，而本仓库的 MILP 是**单日 96 点**模型。
  闭环实现施加的是**每日**上限 `load + P_charge − P_discharge ≤ cap`，
  比月约束更紧，因此得到的是最优解的**下界**（可能少赚），不是"月内最优"。
- `transformer_kva = 3200` 是按内置数据 7 月月峰 2399 kW、功率因数 0.9 折算（≈2666 kVA）
  后取的工程常见配置（2×1600 kVA）。换用户时这是第一个要改的数。
- 1583 号讲的是**销售侧基本电费**，与容量补偿机制、需量响应等新政各省市另行规定，本仓库未建模。


`data/battery/battery_params.csv`。
